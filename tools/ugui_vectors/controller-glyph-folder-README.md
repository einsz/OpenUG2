# Controller glyph folder vectors

The index is a sanitized list of the user-authorized PNG folder's 66 functional
file/key identities, family/category/language metadata, dimensions and hashes.
Each individual PNG was independently read, its signature, IHDR and chunk CRCs
validated, decoded with Pillow 12.3.0, and its full file and row-major RGBA8
SHA-256 compared with supplied export metadata. All 66 comparisons agreed.
No image bytes, pack offsets, source paths from original symbols, extraction
instructions or analyst evidence paths are included.

This acquisition provenance applies individually to every index entry. Its
file/key identity, dimensions and digests are observed file facts; category
and language are inherited functional metadata with inferred semantic meaning,
not verified retail runtime behavior. Exact relative filenames and resource
keys are required interoperability identifiers [interop].

The case JSON is freshly authored demo acceptance input/output, not captured
original runtime output. `complete` means the user-supplied PNG files matching
the index are present under the selected root. Cases with mutations are
hypothetical test arrangements; apply them only to a disposable test copy.
The case JSON's shared provenance applies individually to F-1 through F-14:
each is a freshly authored D arrangement and expected outcome, rather than an
observed original input/output pair. No case contains original artwork.
The corpus itself must not be bundled with recreated implementation or tests.
For valid cases compare index membership and statuses, and check visible gallery
and action-slot art at both approved resolutions. For malformed cases use the
recreated loading boundary and assert rejection without suppressing other valid
records. Input caps or digest checks may reject a mutation before PNG decode;
this is acceptable when reported as the applicable conceptual failure reason.
