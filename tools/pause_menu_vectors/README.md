# Synthetic acceptance vectors

All vectors were authored independently from the screenshot measurements, observed retail resource metadata, and coordinator integration requirements. They are not original runtime captures, contain no original assets, and make no original-code assertions. Geometry uses top-left 640×480 coordinates (convert to the base centered canvas by subtracting [320,240]). Tolerance for visual bounds is 2 virtual units per edge; the mathematical transform and state expectations are exact. Decimal pixel bounds in geometry.json are rounded to three decimal places and allow 0.001 pixel numerical comparison tolerance; this numerical tolerance is distinct from the visual measurement tolerance. `geometry.json` tests uniform scaling, centering, and inverse-pointer mapping. `interaction.json` uses a synthetic supported catalogue with independently authored action identifiers. It tests requested pause integration, never the original game's catalogue or original hidden behavior.

Expected presentation: genuine runtime retail UI art, condensed slanted retail font, horizontal selector, selected green glow, one caption, text-only PC Back/Continue controls, and driving scene visible behind translucent panel. Compare output against SPEC.md regions rather than bundling screenshot crops. If genuine assets are unresolved, report the visual check as unavailable; do not pass it with placeholders.

Each interaction case starts independently from its stated preconditions with invocation counters reset to zero. Omitted view means top-level. The catalogue and event names are test fixture vocabulary authored for these cases, not recovered identifiers. The disabled-action case uses the explicit disabled fixture in interaction.json; it asserts only that activation cannot invoke that disabled action. Checks that preserve existing engine behavior compare against a recorded baseline for that same supported action or lifecycle; the capture supplies no missing baseline behavior. If that baseline or required genuine resources are unavailable, mark the affected check unresolved rather than invent an expected result.

Visual acceptance uses inspection of the rendered regions and their measured bounds at the listed viewports. Check the described colors, rounded contours, horizontal glyph arrangement, one caption, label containment, text-only pills, and visibility of scene detail through the fill. Exact original tint, opacity, font metrics, and pause animation timing remain unknown. OPACITY.md and MOTION.md now establish explicit D targets and require actual paired-render/animated-sequence measurement; visual impression alone no longer passes those corrections.

`corrections.json` adds independently authored expectations for identified artwork lookup keys, native dimensions/alpha bounds, arrow alias equivalence, measured label ink, and surface/marker silhouettes. Resource metadata and equality are observations of retail data; they contain no retail pixel payload. Image lookup checks require authorized runtime inputs and should be unresolved when those inputs are absent. Label pixel bounds were measured in narrow original screenshot ROIs using min(R,G,B)>100; thresholds 70–140 produced extents differing by at most 2 pixels. Normative output acceptance retains the wider ±2 virtual-unit visual tolerance, not exact screenshot pixel equality. Corner extent is an approximate inferred visual range rather than an asserted native asset radius. Screenshot crops/contact sheets are retained only in analyst evidence.

`opacity.json` contains synthetic input/output examples for estimated D net scene retention and neutral intercept bands in OPACITY.md. `motion.json` contains synthetic catalogue/time/input cases for D marker movement, arrow availability, rail pointer input, rapid changes and visibly rendered glow. The highlight curve comes from previously approved base GUI data facts; its pause assignment and the 160 ms marker duration are explicit integration choices. These vectors were freshly authored with analyst `opacity/scripts/write_vectors.py` and contain no original image payload. Passing their arithmetic/state cases cannot replace actual renderer menu-on/menu-off pairs and timed captured sequences at both acceptance sizes. The historical static marker [50,188.4] vector describes the first entry; later entries use MOTION.md's dynamic positions.

`authored.json` tests AUTHORED.md metadata and previously independently evaluated object-alpha samples, plus D reopen/paired-render/priority requirements. These are evaluated package semantics, not original execution captures or net framebuffer alphas. Supported authored properties/tracks take precedence over approximate OPACITY bands and generic MOTION timings. Apply generic motion arithmetic vectors only to the explicitly D fallback where no supported authored track defines that behavior; all synchronization/input requirements remain binding. Authored parity requires actual matched reference-render/menu-off captures, never just these object-alpha samples.

`binding.json` records directly decoded original-data identities/local geometry and independently authored two-action catalogue cases for BINDING.md. Extraction uses the specified compressed retail input and analyst-only scripts; no implementation source or original executable was used. Pool order in the metadata is identifier order, never a retail action order. The two-action fixtures state supplied application actions, and do not claim the original screenshot displayed quit. Local centered coordinates in object metadata differ from the top-left screenshot acceptance coordinates. These vectors contain no retail pixel/font/package payload.

`behavior.json` (round 2, BEHAVIOR.md) is generated by analyst `round2/scripts/write_vectors.py`. Its arrow-blink and exit-fade samples are evaluated from decoded original package data. Its slide, marker-snap, arrow-visibility, pointer and resume-latency cases follow the user's authoritative decisions of 2026-10-13; the `pointer_click_*arrow*` and `pointer_arrow_*` cases follow the user's 2026-10-14 observation that a visible arrow click steps like Left/Right and a hidden arrow is inert (press-down timing, 26×26 hit box, no auto-repeat and gesture-arming details are D). The former `pointer_click_inert_left_arrow`/`pointer_click_inert_right_arrow` cases were removed. The slide offset, size and alpha tables come from the exponential ease-out law in BEHAVIOR R1.5-R1.7, which the user declared identical to the original. Cases tagged D are integration choices. None of these are original runtime captures.

`quit_dialog.json` (round 3, QUIT_DIALOG.md) is generated by analyst `round3/scripts/write_vectors.py` from decoded original data (`GLOBAL/InGameCommon.lzc` package `0x191A579C`, global texture keys, `LANGUAGES/ENGLISH.BIN.bacc` string keys). Its object geometry, resources, string keys and `evaluated_colour_samples` are data facts evaluated with the base track semantics, not runtime captures. Cases `QD-*` tagged "User decision 2026-10-14" follow the user's authoritative Round 3 answers (quit-to-main-menu text profile, default focus on the right/"No" button, hover focus, no-wrap Left/Right, Escape/Back and right-click cancel, release-activation only when the press began on the button, x0.40 darkening only, pills hidden, selection preserved, game paused, results on the input frame with any exit fade at most 100 ms and never delaying them); cases tagged D are analyst integration defaults listed in QUIT_DIALOG.md Q8.3 (including the Yes/No label keys, which no data binds to this message). `text_profiles` marks profile A selected and the frontend profile B and the lost-progress variant unused; `pause_quit_item_caption` gives the required pause caption key. The label-key search behind the D label choice is reproduced by analyst `round3/scripts/label_key_search.py`. No retail payload is included.

## Supersession by SPEC_GUI_ART (2026-10-14)

`docs/cleanroom-settings/SPEC_GUI_ART.md` (approved) replaces parts of the earlier pause rules. What changed here:

* `quit_dialog.json` (round 3, Yes/No dialog on `IG_GenericDialog_SMALL`) and its checker/harness were removed: the pause quit confirmation is `UI_InGameDialog` with OK/Cancel, default focus Cancel (`test-vectors-gui/tvg10_dialogs.json`, `tools/gui_art_test.c`).
* `behavior.json`: the exponential slide cases (`slide_one_step_table`, `icon_alpha_vs_distance`, `slide_right_one_step_items`, `slide_retarget_mid_animation`, `slide_reversal_mid_animation`, `slide_frame_rate_independence`) are skipped (cubic Hermite over 0.3 s, `tvg08`); position samples inside the other cases are compared only at t = 0. `authored_exit_fade` and `resume_immediate_*` now assert exit-then-resume (320 ms, `tvg11`) instead of an immediate resume.
* `corrections.json`: cases 0, 1, 3, 4, 5, 6 describe application-chosen art (icon/arrow lookup keys, selector and caption surfaces, marker); the art now comes from the package's own objects and resources. Case 2 (PC pill label ink) is still checked.
* `binding.json`: the captions follow SPEC_GUI_ART 2.2 (`Quit to Main Menu`), written slot colours are white/255.
* `interaction.json`, `motion.json`, `geometry.json`, `authored.json`, `opacity.json` run as before against the new adapter (synthetic catalogue through the `ps_open_entries` test seam), apart from the cases their checkers already supersede.
