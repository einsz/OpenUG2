# Test vectors

All vectors in this directory are **synthetic**: they were generated by the
analyst from the rules written in `../SPEC.md`. They contain no copied original artwork, source text, or retail data records.
Required format constants and short runtime resource tokens [interop] may
appear within the independently authored synthetic records. Byte layouts were
cross-checked by parsing the synthetic files with the same analyst-side parser
that was used on the retail files (so a parser that accepts the retail files
accepts these, and vice versa).

| File | What it is | How it was obtained | Spec section |
| --- | --- | --- | --- |
| `hash_vectors.tsv` | ASCII input -> 32-bit name hash | Computed with the hash in SPEC 2 | 2 |
| `minimal_package.hex` | 1336-byte screen package: 1 group, 1 image button, 1 text, 2 scripts on the button (incl. a looping track and one timed event), object + package message responses, target index | Built by hand from the SPEC 3 layout | 3 |
| `minimal_package.expected.json` | Decoded field values for `minimal_package.hex` (colours already converted to R,G,B,A order) | Parsed back with the analyst parser | 3 |
| `track_eval_vectors.json` | Base value + delta keys -> evaluated value at sample times (clamp and loop cases, constant track, zero-length script) | Reference evaluation of SPEC 3.5.3 | 3.5.3 |
| `string_table.hex` | 620-byte localisation table with 4 entries and one remapped high byte | Built by hand from SPEC 8.3 | 8.3 |
| `string_table.expected.tsv` | label -> hash -> decoded text | Same | 8.3 |

Hex files: one line per 16 bytes, `offset  b0 b1 ...`, offsets in hex.

Notes for `minimal_package`:

* Script, message and object identifiers inside it are hashes of
  made-up names; only the hash values matter.
* Object guids are 0x100 (group), 0x101 (image, button), 0x102 (text).
* The image button's highlight script is 400 ms long, flagged looping, and
  emits one event (message hash `2085de1c`, target 0xFFFFFFFF = application)
  at t = 400 ms.
* The package response for the right mouse button re-posts the Back action
  to the screen itself (command 1, target 0), mirroring the observed
  retail pattern (SPEC 4.6).

Notes for `track_eval_vectors.json`:

* Samples of looping tracks are given only for times inside `[0, length)`,
  because the script wraps time before the track is evaluated (SPEC 3.5.4).
* Colour values are clamped to 0..255 after adding base and delta and are
  rounded to the nearest integer.

## Amendment 2 vectors (round 2)

All synthetic. Generated by the analyst from the rules in SPEC 13–16,
then decoded back with independent analyst decoders. JDLZ was decoded with
the repository's `tools/jdlz.py`. HUFF was decoded with an analyst decoder
written from the public psx-spx description, the same decoder that
reproduced the 6 retail HUFF packages byte-for-byte. Texture and font
vectors were re-parsed with the analyst readers used on the retail files.

| File | What it is | Spec section |
| --- | --- | --- |
| `jdlz_vectors.json` | 4 cases: literals only; near matches and a long run; a far match (distance > 16); 12 matches, forcing a flag-B refill on a literal iteration. Each case has plain hex, stream hex (with the 16-byte header) and the token list | 13.1, 13.2 |
| `huff_vectors.json` | 2 cases: plain text; runs plus an escaped literal equal to the escape symbol. Each case has plain hex, stream hex (with the `HUFF` wrapper), escape byte and canonical code table | 13.1, 13.3 |
| `tpk_table.hex` + `tpk_table.expected.json` | Table-variant texture pack with 5 textures: 4x2 BGRA8; 8x8 DXT1 with 2 levels, including 3-colour/transparent blocks; 8x4 DXT3 (a 4-colour block whose c0 <= c1); 4x4 palettized; a 30-character name (stored truncated, key from the full name). Expected values give key, size, format, level count, data offset and the level-0 RGBA of each texture | 15 |
| `tpk_slots.hex` + `tpk_slots.expected.json` | Compressed-slot pack: 2 JDLZ blobs (pixels +  124-byte record + 32-byte descriptor), absolute blob offsets | 15.6 |
| `font_chunk.hex` | Font chunk `0x00030201`: 6 glyphs (space, A, V, period, g with descender, U+2019), kerning lists, version-0x19E texture block, 64x32 atlas | 16.1–16.3 |
| `font_layout_vectors.json` | Strings → quads (virtual units, texture coordinates) under 16.5, including kerning, scale 0.5 and a `^` line break | 16.5 |
| `bundle_compressed.hex`, `bundle_raw.hex`, `bundle.expected.json` | The round-1 `minimal_package` carried as chunk `0x00030210` (hash + JDLZ) and as `0x00030203` (raw); the hash equals hash(upper-case package name) | 3.2, 14.3 |

Notes: DXT colour interpolation in the expected RGBA uses integer division
(floor), with no GPU rounding; accept ±1. The palette bytes in `tpk_table`
are stored B,G,R,A (SPEC 15.7 discusses why the order is uncertain for
retail palettes).

## Amendment 4 vectors

These contain no retail image pixels. `corner_transform_vectors.json` uses
synthetic signed-size quads and UV-labelled vertices; expected projected
vertices were freshly calculated with the quaternion equation in 20.2. Test
all components, particularly x/y half turns, signed dimensions and preserving
UV association. `ps2_icon_codec_vectors.json` uses 512 synthetic bytes and a
synthetic 16-entry palette with deliberately unequal R/B channels and alpha
edge cases. The analyst's independent calculator checks that the observed
swizzle maps every nibble exactly once; compare indices, sample RGBA and the
complete decoded RGBA hash. `original_visual_policy_vectors.json` contains
input/status/presentation cases for 20.1–20.5, derived from user direction and
observed source availability. Generation command (analyst-only) was
`python3 cleanroom/analysis/scripts/round4_vectors.py`; no executable or
implementation was run. Required original-resource provenance and original
image comparisons stay outside this vector directory.

Reviewer round-4 correction: `font_layout_vectors.json` explicitly records
cell height 21 and leading 0. In `AV^VA` the second line starts at 21
unscaled units (quad y extents 25..39), matching amended 16.5.
