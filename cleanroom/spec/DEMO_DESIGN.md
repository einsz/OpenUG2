# Demo composition and usability requirements — reviewed 2026-10-13

Status: reviewed; approval hashes are recorded in REVIEW.md. This document specifies **demo configuration (D)**. It does not assert additional retail behavior. It preserves SPEC 20.1–20.7, RESTORATION_PC_PILLS and the reviewed console cases. Existing retail geometry remains authoritative for original-screen rendering. These requirements apply to authored demo examples and their tooling.

Evidence basis: the reviewed six PC reference observations in SPEC 19 and fresh observation of all thirteen demo pages, modal states and six representative 1280×720 pages. The audit found clipped browser arrows, faint enabled dialog labels, a package example promising an invisible button, confusing availability guidance and mixed-scope option naming. It did not establish general text overlap or broken interaction on all pages.

## D1 Shared composition

1. Use the 640×480 coordinate system and uniformly scaled, clipped viewport in SPEC 1.1. Acceptance sizes are 1280×960 and 1280×720. Every enabled control's visible silhouette and hit region fit within the viewport. Browser/list controls keep at least 8 virtual units between their outer visible silhouette and its edge (D margin); retail package geometry is exempt from this extra demo margin.
2. Titles on authored non-carousel pages use the original font, accent palette, scale 0.8 and ink left/top anchors approximately (-288,-214), following SPEC 19 item 26 (±1 virtual unit for those anchors). A main-menu carousel example instead uses SPEC 6.4/19 item 10, including its right-aligned title. Original viewers retain the selected package's authored title.
3. Each authored page has a dark title/header region and a deliberately grouped body region. A settings/list/keyboard/date/dialog-launcher/catalogue body uses genuine light panel art with rounded corners, dark text and a focused dark backing. A carousel uses the original dark outer panel and light icon band. A car page uses the genuine header/carousel band and faint lower stat band. Panels use genuine runtime assets and SPEC 20.2 transforms; no generated border/corner artwork is authorized. This grouping is a D composition choice based on the reference hierarchy, not a claim that each demo has a retail equivalent.
4. Normal body/value text uses scale 0.7; headings use accent; ordinary light-panel text uses the approved dark palette; explanatory captions use scale 0.5–0.55. Resource browser filenames may use 0.45–0.5 in a tooling view. Do not reduce ordinary control labels to browser-sized text to fit additional diagnostics.
5. Main content, explanatory text and active profile chrome have disjoint ink/visible bounds. Leave at least 8 virtual units between unrelated content groups (D spacing). Default examples display short user-facing captions. Numeric hashes, flag values, durations, pack paths and internal event counters are available in a separately identified diagnostic view. The normal example does not display long instructions below every sample.
6. Default PC chrome is the original text-only help strip and pills, with geometry, labels, hover animation and actions under SPEC 20.7. Preserve the dark player box, exact slots and modal hiding. Do not add mouse/key/controller badges or a PC Help pill. Demo-specific additional actions may use available original slots and short text-only labels; label this as D mapping. No second action strip is drawn. Explicit PS2/Xbox selection uses only genuine family art and the one console strip. Shared resources that loaded successfully are not described as missing.
7. Missing art/media is omitted as required by SPEC 20.1, with a concise category-specific demo status in a readable caption region. Omission of unavailable 3D scenery alone is permitted and must not be repaired with invented cars, scenery, logos or decorative artwork.

## D3 Acceptance sequences

- Capture every page with loaded PC originals, selected PC profile, at both acceptance sizes. Verify title/body/chrome separation, intended hierarchy, genuine assets, family status and reachable full control silhouettes. Include first/last browser positions and first/last car.
- Capture enabled focused/unfocused dialog labels at rest and transition endpoints. The original raster glyph shape has a filled interior distinguishable from its button, with the approved palette/alpha semantics. Compare two-choice geometry and labels to SPEC 19/C3/C6; preserve authentic focused-label pulse. Test click/Accept/Back, modal input exclusivity and restored chrome. This filled-ink test addresses observed outline-only labels without inventing an arbitrary contrast ratio or overriding original unfocused grey.
- Activate each promised example control and observe its value, selection, text or result change. Do not classify a page as interactive solely because its bottom Back pill works. Explicit unavailable examples report their missing category and do not promise an invisible control.
- Switch PC → PS2 → Xbox → PC with each supplied source and with each source absent. One strip, correct family/status and available genuine art persist; absence never produces fabricated art. PC returns to original text-only pills.
- Keep existing reported passing input/codec/viewport/GL checks. These checks complement visual acceptance; they do not prove page composition matches retail.

## Unknowns/Ambiguities

No original execution occurred in this phase. Only six retail PC stills are available; there is no retail screenshot for most demo widget groupings. D margins, group placement and diagnostic separation are intentional demo decisions. Retail Xbox/PS2 action-token bindings and exact glyph baselines remain unknown. The fresh audit did not test all pointer/key combinations or every original screen. It established no general page-1 text overlap. Genuine 3D car/background/movie rendering is outside this GUI composition scope. The exact root cause of outline-only unfocused labels is not specified here.
